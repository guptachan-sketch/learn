Agentic RFP Evaluator

A plain-language guide to what the app does, how it reaches a supplier ranking, which AI model it can use, and what to know before sharing it.

Decision-support tool The score is not a purchasing decision. A person should verify the proposal evidence and risks.

Important for the public deployment: anyone can use this app without signing in. Evaluation history and criteria are shared with every visitor, who can edit the criteria. Do not upload real or confidential supplier documents or enter a valuable personal API key.

What the app does

The app helps compare supplier proposals against a set of evaluation criteria. It reads text from uploaded PDFs, produces a scorecard for each supplier, calculates weighted scores and peer comparisons, and displays a ranked leaderboard. You can review the evidence, explanations, warnings, and risks, then download a run as JSON.

It supports two assessment modes:

  • Demo mode: searches proposal text for category-related keywords. It needs no AI service and no API key. Its scores are only a demonstration, not an AI assessment.
  • OpenAI API mode: asks a selected OpenAI model to return criterion scores, explanations, evidence, risks, and a summary. Model output can be mistaken or influenced by text in a proposal.

How a comparison works

The app opens with an Overview dashboard, followed by horizontal tabs for Criteria, Evaluate suppliers, Leaderboard, Scorecards, and History. The overview and leaderboard include visual supplier comparisons. In Scorecards, each supplier has a separate tab so you can review details without scrolling past every supplier.

1. Set the criteriaChoose which criteria are active and their weights. Active weights must add to 100%.
2. Choose proposalsUse the six bundled fictional examples for a quick demo, or upload your own text-based PDFs and enter supplier details.
3. Assess each proposalDemo mode uses keywords; OpenAI API mode sends extracted text to the selected OpenAI model.
4. Check and normalizeThe app checks the response shape, fills missing scores with zero, clips scores to their allowed range, and shows warnings.
5. Calculate scoresPython calculates weighted scores, criterion benchmarks, performance percentages, and ranks.
6. Review and exportInspect color-coded evidence and risks in each supplier's scorecard tab, and download the run as JSON.

Color key in the scorecards: green means strong, amber means review, and red means needs attention. The numeric score is shown as well so color is not the only indicator.

How ranking is calculated

The absolute score is the weighted sum of each criterion score divided by its maximum. The PPI is a weighted average of each supplier's performance relative to the best supplier in that run for each criterion. The leaderboard sorts by PPI (high to low), earlier submission date, higher experience rating, and then supplier name alphabetically.

Which AI model and API key does it use?

  • The OpenAI API screen defaults to gpt-4o-mini, called through the OpenAI Python client.
  • The OpenAI model name is editable in the app; a different OpenAI model that supports JSON mode can be entered.
  • The app does not include a provider API key in the public source code, SQLite database, or checked-in configuration.
  • In OpenAI API mode, the person using the app enters their own OpenAI API key in a password-masked field. The app passes that value to the OpenAI client for the request; it does not read a key from Streamlit secrets or an environment variable.
  • Demo mode makes no LLM request and needs no key.
  • OpenAI API requests include the supplier name, active criteria, and up to 60,000 characters of extracted proposal text. OpenAI may charge the key owner for use. Check its terms and data-retention policy before sending proposal material.

Password masking only hides the characters on screen; it does not make the key safe to use on an untrusted public app. Prefer a private, authenticated deployment for Live mode.

Security and privacy concerns

ConcernWhat it means in everyday termsPractical advice
No access control There is no sign-in. Visitors share completed run history and anyone can edit criteria, which affects later evaluations. Keep confidential supplier data out of this public deployment. Add authentication and authorization before using sensitive data.
Proposal text can influence AI A PDF may contain instructions intended to manipulate an AI model. The prompt asks the model to ignore such instructions, but this is not a reliable security barrier. Treat AI scores as suggestions. Review every important score against the original proposal and test with deliberately adversarial documents.
Third-party data sharing OpenAI API mode sends extracted proposal text to OpenAI. Demo mode does not. Use only documents you are allowed to share, and review OpenAI's privacy and retention terms.
Public source and public app Anyone can inspect the code and use the hosted app. Public code is not itself a secret leak; the reviewed tracked code contains no API key. Keep keys out of Git, rotate any key that may have been exposed, and do not treat an unlisted app URL as access control.
Database persistence The app writes to local SQLite storage. Streamlit Community Cloud storage may be reset during restarts or redeployments, and the same app instance serves multiple visitors. Do not use this local database as durable or private production storage. Use a properly secured managed database if needed.
PDF limitations The app extracts selectable text. Scanned image-only PDFs need OCR and may not be read correctly. Check extracted evidence and page references before relying on results.

What it stores

The SQLite database contains evaluation criteria, run status and dates, supplier metadata and rankings, and criterion-level scores, evidence, and justifications. It is stored alongside the app locally; on Community Cloud this storage is not guaranteed to persist. Runs and criteria are shared by all visitors in this public version.

Recommended use right now

  1. Keep the hosted app limited to fictional or non-sensitive sample documents.
  2. Use Demo mode unless you have a legitimate reason to send text to an AI provider.
  3. Do not enter a valuable personal API key into the public app. If you already used a key and suspect it was exposed, revoke it and create a replacement.
  4. Before production use, add authentication, per-user access checks, durable managed storage, operational logging, and a tested privacy/security review.
  5. Always have a qualified person verify proposal evidence and make the final procurement decision.

Project files

  • app.py contains the Streamlit interface and workflow.
  • documents.py extracts text from PDF files and creates fictional samples.
  • evaluation.py handles the Live LLM request, demo scoring, validation, calculations, and ranking.
  • database.py creates and reads the SQLite tables.
  • tests/ contains automated checks for scoring and response validation.

The app includes six fictional supplier proposals with extra due-diligence notes. Select “Try the six bundled fictional proposals” for a quick demo. Their claims and scores are synthetic and must not be treated as real procurement evidence.
